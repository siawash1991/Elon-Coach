# نقشه راه: تبدیل Elon-Coach به «مغز متفکر» (شورای منتورها)

> هدف: یک چت‌بات که در آن با ترکیبی از **ایلان ماسک، اندرو هوبرمن، وارن بافت و چارلی مانگر** به‌عنوان یک «شورای ذهنی» گفتگو می‌کنی — با پشتوانه یک پایگاه دانش زنده به سبک **LLM Wiki کارپاتی** که در **Obsidian** هم قابل مرور است.

---

## ۱. نتیجه تحقیق: سه مسیر ممکن و انتخاب نهایی

| مسیر | توضیح | نتیجه |
|---|---|---|
| آموزش مدل شخصی (nanochat کارپاتی) | آموزش یک LLM کوچک روی داده منتورها | ❌ رد — هزینه GPU بالا (صدها دلار)، کیفیت بسیار پایین‌تر از مدل‌های آماده، فارسی ضعیف |
| RAG کلاسیک (vector DB + embedding) | ذخیره embedding ها، جستجوی برداری در هر پیام | ❌ رد برای MVP — زیرساخت اضافه، دو مرحله API، پیچیدگی بدون سود واقعی در این مقیاس |
| **LLM Wiki کارپاتی + مدل آماده از OpenRouter** | دانش یک‌بار «کامپایل» می‌شود و مستقیم در context می‌رود | ✅ **انتخاب نهایی** |

**چرا LLM Wiki؟** نکته کلیدی الگوی کارپاتی (گیست آوریل ۲۰۲۶): تا وقتی wiki زیر ~۱۰۰ هزار کلمه است، **اصلاً به RAG و vector DB نیاز نداری** — دانش فشرده‌شده مستقیم داخل system prompt جا می‌شود. یک تماس API به‌جای دو تماس، بدون دیتابیس، بدون embedding. و چون همه‌چیز Markdown با wikilink است، همین پوشه را به‌عنوان vault در Obsidian باز می‌کنی و graph view مجانی می‌گیری.

---

## ۲. معماری

```
Elon-Coach/
├── brain/                        ← این پوشه = vault اوبسیدین
│   ├── CLAUDE.md                 ← اسکیمای wiki: قوانین نگهداری (قلب الگوی کارپاتی)
│   ├── index.md                  ← فهرست همه صفحات + خلاصه یک‌خطی
│   ├── log.md                    ← لاگ append-only از هر ingest/query/lint
│   ├── sources/                  ← منابع خام، فقط-خواندنی (LLM هرگز تغییرشان نمی‌دهد)
│   │   ├── musk/  huberman/  buffett/  munger/
│   ├── wiki/                     ← صفحات تولیدشده توسط ایجنت
│   │   ├── people/               ← elon-musk.md, charlie-munger.md, ...
│   │   ├── concepts/             ← first-principles.md, circle-of-competence.md,
│   │   │                            inversion.md, dopamine-protocols.md, ...
│   │   └── frameworks/           ← mental-os.md (مهاجرت از translations.ts فعلی)
│   └── personas/                 ← خروجی کامپایل‌شده برای چت‌بات
│       └── mentor-council.md     ← system prompt نهایی (~۴-۶ هزار توکن)
├── worker/                       ← Cloudflare Worker: پروکسی امن OpenRouter (کلید API مخفی می‌ماند)
└── (اپ React فعلی + صفحه چت جدید)
```

**جریان دانش:** منبع خام → ingest توسط ایجنت → به‌روزرسانی صفحات wiki → کامپایل مجدد `mentor-council.md` → چت‌بات همیشه از آخرین نسخه پرسونا استفاده می‌کند.

**جریان چت:** مرورگر → Worker (کلید امن) → OpenRouter → پاسخ استریم. **فقط یک تماس API در هر پیام.**

## ۳. اسکیل‌ها

1. **ponytail** (`DietrichGebert/ponytail`) — نصب به‌عنوان اسکیل always-on تا هر کدی که ایجنت می‌نویسد از نردبان YAGNI رد شود (به‌طور میانگین ~۵۰٪ کد کمتر). برای Worker و UI چت دقیقاً همان چیزی است که می‌خواهی.
2. **اسکیل سفارشی `/ingest <path>`** — منبع جدید را می‌خواند، صفحات wiki مرتبط را به‌روز می‌کند، index.md و log.md را آپدیت می‌کند (طبق اسکیمای CLAUDE.md).
3. **اسکیل سفارشی `/compile-persona`** — از روی wiki، فایل `mentor-council.md` را بازتولید می‌کند: سبک گفتار، اصول تصمیم‌گیری، جملات معروف و «صدای» هر منتور + قوانین تعامل شورا.
4. **اسکیل سفارشی `/lint-wiki`** — ماهانه: تناقض‌ها، صفحات یتیم، لینک‌های شکسته.

## ۴. مدل و هزینه (OpenRouter)

کارمزد OpenRouter: بدون مارک‌آپ روی توکن؛ فقط ۵.۵٪ روی شارژ اعتبار.

| مدل | ورودی /۱M | خروجی /۱M | نظر |
|---|---|---|---|
| **Gemini 3 Flash Preview** ✅ پیشنهاد اصلی | $0.50 | $3.00 | فارسی خوب، سریع، ارزان — بهترین تعادل برای MVP |
| DeepSeek Chat | $0.32 | $0.89 | ارزان‌ترین؛ فارسی متوسط — گزینه پشتیبان |
| Claude Haiku 4.5 | $1.00 | $5.00 | کیفیت پرسونای بهتر؛ برای ارتقا بعد از MVP |
| Gemini 3.5 Flash | $1.50 | $9.00 | فقط اگر کیفیت Flash 3 کافی نبود |

**تخمین هزینه هر پیام** (system prompt پرسونا ~۵k توکن + تاریخچه ~۲k + پاسخ ~۵۰۰ توکن):

- Gemini 3 Flash: ≈ **$0.005 در هر پیام** → ۱۰۰۰ پیام ≈ $5
- استفاده شخصی MVP (۲۰-۳۰ پیام در روز): **زیر ~$5 در ماه**
- با فعال‌کردن prompt caching روی system prompt ثابت، هزینه ورودی باز هم کمتر می‌شود.

هزینه ساخت و نگهداری wiki: تقریباً صفر — با همین Claude Code (اشتراک موجود) انجام می‌شود، نه با API.

## ۶. چیزهایی که عمداً انجام نمی‌دهیم (YAGNI)

- ❌ Vector DB / embedding / pipeline ایندکس — تا قبل از ۱۰۰k کلمه لازم نیست
- ❌ آموزش یا fine-tune مدل — پرسونا با prompt + دانش wiki به‌مراتب ارزان‌تر و بهتر درمی‌آید
- ❌ بک‌اند دیتابیس‌دار — تاریخچه چت در localStorage مرورگر کافی است
- ❌ فریم‌ورک‌های LangChain و مشابه — یک fetch ساده به OpenRouter کفایت می‌کند
