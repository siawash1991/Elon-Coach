# فاز ۰ — زیرساخت (نیم روز)

## گام ۰.۱ — اسکلت پوشه‌ها

```
brain/

├── index.md             # فهرست همه صفحات + خلاصه یک‌خطی هر کدام
├── log.md               # لاگ append-only: [INGEST] [QUERY] [LINT] [COMPILE]
├── sources/             # فقط-خواندنی؛ ایجنت هرگز تغییرشان نمی‌دهد

```

## گام ۰.۲ — محتوای `brain/CLAUDE.md` (اسکیمای ویکی)

این فایل قلب الگوی کارپاتی است؛ باید دقیقاً این بخش‌ها را داشته باشد:

1. **نقش‌ها**: انسان = انتخاب منبع و پرسیدن سوال؛ ایجنت = همه بوک‌کیپینگ (خواندن، خلاصه‌سازی، لینک‌دهی، به‌روزرسانی index و log)
2. **قواعد نام‌گذاری**: فایل‌ها kebab-case انگلیسی (`first-principles.md`)؛ عنوان H1 دوزبانه (انگلیسی + فارسی)
3. **قالب صفحه wiki**: front-matter شامل `type` (person/concept/framework)، `mentors` (کدام منتورها مرتبط‌اند)، `sources` (لیست فایل‌های منبع)، `updated`
4. **قواعد لینک**: wikilink اوبسیدینی `[[first-principles]]`؛ هر صفحه حداقل ۲ لینک ورودی/خروجی؛ صفحه یتیم ممنوع
5. **قواعد ingest**: هر منبع جدید → به‌روزرسانی حداکثر ۱۰-۱۵ صفحه مرتبط → یک خط در `log.md` → به‌روزرسانی `index.md`
6. **قاعده طلایی**: `sources/` غیرقابل تغییر است؛ `wiki/` کاملاً متعلق به ایجنت است؛ تناقض بین منابع حذف نمی‌شود بلکه در بخش «اختلاف‌نظرها» ثبت می‌شود (مثلاً بافت و ماسک درباره ریسک)

## گام ۰.۳ — نصب اسکیل ponytail

```bash
npx skills add DietrichGebert/ponytail   # یا کپی SKILL.md به .claude/skills/ponytail/
```

از این به بعد هر کدی که برای Worker و UI نوشته می‌شود از نردبان YAGNI رد می‌شود:
«لازم است اصلاً وجود داشته باشد؟ → stdlib انجامش می‌دهد؟ → قابلیت بومی پلتفرم؟ → وابستگی موجود؟ → در یک خط جا می‌شود؟»

## گام ۰.۴ — سه اسکیل سفارشی در `.claude/skills/`

| اسکیل | فایل | کار دقیق |
|---|---|---|
| `/ingest <path>` | `.claude/skills/ingest/SKILL.md` | منبع را می‌خواند → طبق CLAUDE.md صفحات wiki را می‌سازد/به‌روز می‌کند → index.md و log.md را آپدیت می‌کند → گزارش: «N صفحه تغییر کرد» |
| `/compile-persona` | `.claude/skills/compile-persona/SKILL.md` | کل `wiki/` را می‌خواند → `personas/mentor-council.md` را بازتولید می‌کند → سقف سخت: **۶٬۰۰۰ توکن** → در log ثبت می‌کند |
| `/lint-wiki` | `.claude/skills/lint-wiki/SKILL.md` | تناقض‌ها، صفحات یتیم، لینک شکسته، ادعاهای بدون منبع → گزارش + اصلاح خودکار موارد مکانیکی |

## گام ۰.۵ — اتصال Obsidian

پوشه `brain/` را به‌عنوان vault باز کن (Open folder as vault). تنظیمات: «Wikilinks» روشن، «New link format: shortest». از این لحظه graph view نقشه مغز است.

**معیار پذیرش فاز ۰:** اسکلت + CLAUDE.md کامیت شده؛ `/ingest` روی یک فایل تستی اجرا شده و index/log درست آپدیت شده‌اند.

# فاز ۲ — کامپایل پرسونا (نیم روز)

## ساختار دقیق `personas/mentor-council.md` (سقف ۶k توکن)

```
1. هویت کلی (~200 توکن)
   «تو شورای ذهنی هستی: ماسک، هوبرمن، بافت، مانگر...»

2. پروفایل هر منتور (~800-1000 توکن هر نفر)
   - صدا و لحن (ماسک: رک، مهندسی، بی‌حوصله با بوروکراسی / مانگر: طعنه‌زن، وارونه‌ساز...)
   - ۵-۷ اصل تصمیم‌گیری با ارجاع به [[صفحه wiki]]
   - ۳-۴ جمله امضایی واقعی
   - حوزه صلاحیت (کی جواب بدهد، کی سکوت کند)

3. قوانین شورا (~500 توکن)
   - روتینگ: سوال فیزیک/ساخت → ماسک؛ بدن/عادت → هوبرمن؛ پول → بافت؛ قضاوت/سوگیری → مانگر
   - سوال‌های بزرگ: ۲-۳ منتور با دیدگاه‌های متمایز، سپس جمع‌بندی
   - اختلاف واقعی پنهان نشود (بافت درباره ریسک ≠ ماسک)

4. قوانین خروجی (~300 توکن)
   - زبان پاسخ = زبان کاربر (فارسی/انگلیسی)
   - کوتاه و رک؛ بدون چاپلوسی؛ هر ادعا قابل ردیابی به دانش wiki
   - اعتراف به ندانستن خارج از حوزه صلاحیت
```

**تست پذیرش فاز ۲ — ۱۰ سوال طلایی:** («آیا این کسب‌وکار را بخرم؟»، «چطور تمرکزم را برگردانم؟»، «این قطعه را بسازم یا بخرم؟»...) هر پاسخ باید: منتور درست را انتخاب کند، لحن متمایز داشته باشد، و ادعایش در wiki ریشه داشته باشد.

# فاز ۳ — چت‌بات MVP (۱-۲ روز)

## گام ۳.۱ — Cloudflare Worker (`worker/`)

- `worker/src/index.ts` (~۶۰-۸۰ خط با ponytail): یک endpoint `POST /chat`
  - ورودی: `{ messages: [...] }` (تاریخچه از مرورگر می‌آید — بدون دیتابیس)
  - Worker خودش system prompt را اضافه می‌کند (persona در زمان deploy به‌صورت متن import می‌شود: `import persona from '../brain/personas/mentor-council.md'`)
  - فراخوانی `https://openrouter.ai/api/v1/chat/completions` با `stream: true` و پاس‌دادن مستقیم SSE به مرورگر
  - مدل و پارامترها: `google/gemini-3-flash-preview`، `temperature: 0.8`، `max_tokens: 1024`
  - `models` fallback در بادی درخواست: `["google/gemini-3-flash-preview", "deepseek/deepseek-chat"]` (OpenRouter خودش failover می‌کند)
- امنیت: `wrangler secret put OPENROUTER_API_KEY`؛ CORS فقط دامنه GitHub Pages؛ سقف ۳۰ پیام تاریخچه و ۴k کاراکتر هر پیام (rate-limit ساده بدون سرویس اضافه)
- deploy: `npx wrangler deploy` (پلن رایگان: ۱۰۰k درخواست/روز — بیش از کافی)

## گام ۳.۲ — UI چت در اپ فعلی

- `ChatPage.tsx` جدید + یک کارت سوم در `posts.ts` («🧠 شورای منتورها»)
- همان زبان دیزاین موجود (Tailwind کلاس‌های slate/red فعلی)، RTL برای فارسی مثل بقیه صفحات
- state: آرایه پیام‌ها در `useState` + persist در `localStorage` (کلید `council-chat`)؛ دکمه «گفتگوی جدید»
- استریم: `fetch` + `ReadableStream` — بدون هیچ کتابخانه چت
- سوییچ اختیاری «کل شورا / فقط یک منتور» (یک پارامتر `mentor` که Worker به system prompt اضافه می‌کند — ۵ خط کد)

## گام ۳.۳ — سیم‌کشی نهایی

- `VITE_WORKER_URL` در env؛ آپدیت workflow دیپلوی GitHub Pages
- تست دوزبانه + موبایل

**معیار پذیرش فاز ۳:** از GitHub Pages پیام فارسی می‌فرستی، پاسخ استریم‌شده با لحن منتور درست می‌گیری؛ کلید API هیچ‌جای فرانت نیست؛ refresh تاریخچه را حفظ می‌کند.
